# Hard tool gate for Claude Code subagents

Per `.agent-harness/DELEGATION-CONTRACT.md`, a "hard tool gate" means the `tools:` field in a persona's `.claude/agents/<persona>.md` frontmatter is a runtime allowlist enforced by the Claude Code engine itself at spawn time, not merely a convention written into the prompt that the model could choose to ignore. A subagent spawned as a restricted persona — e.g. `auditor` (`Read, Glob, Grep, Bash`) — receives a tool registry containing only those listed tools, so `Write`, `Edit`, and `Task` are physically absent from its tool table and cannot be invoked even if an instruction in its context tries to direct it to use them. This is categorically stronger than the "portable floor" prompt block also defined in the contract, which relies on the model's compliance rather than the engine's enforcement. The contract notes this mechanism is Claude Code-specific (native `tools:` frontmatter on registered personas); other runtimes approximate it differently, e.g. headless CLI via `--allowedTools` (unlisted tools silently no-op) or opencode via `agent.tools` in `opencode.json`, while unregistered sessions fall back to `general` plus the soft prompt-block convention.
